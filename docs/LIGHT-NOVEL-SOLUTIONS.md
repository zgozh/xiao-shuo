# 柘栯小说：日轻开源方案调研

Research date: 2026-11-17

## 中文结论与本轮采用的实现

社区存在功能完整的日轻客户端和来源扩展体系；本轮没有找到能直接保证“所有日本小说、全部中文译本、所有卷册、长期免登录可用”的公共接口。这是对下列项目和样本的结论，不是对整个互联网不存在其他方案的断言。

| 方案 | 值得参考的部分 | 当前取舍 |
| --- | --- | --- |
| [Yolo 的 Legado 规则](https://github.com/yolo52/Yuedu) | 拷贝轻小说的检索、卷目录、章节行号与插图信息 | 已据此适配，保留来源与 GPL 许可；修正翻页，按章节切分并缓存分卷文本。 |
| [Wenku8 专用客户端](https://github.com/MewX/light-novel-library_Wenku8_Android)、[Flutter 客户端](https://github.com/mikufoxxx/Wenku8_Flutter) | 书目、榜单、分卷目录、离线阅读与本地书库 | 可参考功能和数据组织，不能把作者个人中继、专用凭据或缺少对应源码的二进制当作现成公共接口打包。 |
| [ZWolken 日轻合集](https://github.com/ZWolken/Light-Novel-Yuedu-Source) | 中文译本、国产轻小说、日文原版分别维护 | 提供按需预览导入，并补充分组；不将失效或需要登录的规则全部标成已验证。 |
| [LNReader 插件](https://github.com/LNReader/lnreader-plugins) | 插件独立更新，按语言与站点分离 | 可参考维护方式；其哔哩插件依赖外部 LDS 服务，不作为独立 APK 的默认实现。 |
| [Lightnovel Crawler](https://github.com/lncrawl/lightnovel-crawler) | 跨源搜索、章节抓取、EPUB 导出、失败诊断 | 可参考抓取契约；它需要 Python/服务运行环境，来源总数也不能代表中文日轻覆盖率。 |
| [Novelia](https://github.com/auto-novel/auto-novel) | 文库检索和公开中文 EPUB 卷册 | 作为补充来源，保留中文文件与机翻文件的区别，显示可下载卷册和书目卷册数量。 |

本轮的实际变化不限于分组：新接入拷贝来源的原生搜索、发现列表、卷章目录、正文切片、插图与分卷缓存，同时保留 EPUB 路径。接口预检中，拷贝列出《回复术士》9 个卷册条目，《义妹生活》18 个条目（末条为第16卷，不能把条目数当作本篇卷数），两书首末卷的文本编码和章节边界通过检查；发现接口返回21本。Novelia 的《回复术士》书目列10卷，但仅有9个中文 EPUB，不能称为最新全套。

当前仍受来源收录、网络可达性、译名和网站变更影响。首末卷结构检查不等于逐卷逐章校对，能够搜索也不等于内容完整。下面保留逐项目证据与局限，便于后续更新时复核。

## Finding

I did not find one drop-in, maintained solution that provides a comprehensive catalog of Japanese light novels, Chinese translations, and readable complete volumes for an existing Kotlin Legado-derived app. That is a conclusion about the candidates and sample checks below, not proof that no such project exists anywhere. The open-source projects solve different parts of the problem: Wenku8 clients read one Chinese-language catalog; Legado source collections aggregate site rules; LNReader and Shosetsu load site-specific plugins; crawler projects produce e-books from web chapters; Novelia serves a machine-translation library.

For this app, the smallest practical reuse is to retain Legado's existing source runtime and make any added source groups opt-in and attributable. Use the MIT-licensed ZWolken source set as a candidate feed, after checking the individual rule's login and current behavior. Keep Wenku8 as a separate source-specific path and let its normal site access determine availability; do not depend on a third party's private relay. For Japanese originals, label Kakuyomu/Syosetu-style serialized web fiction as web novels, not published volume catalogs. Treat Novelia EPUB import as a supplemental, volume-by-volume path for the cases where its public library has the title.

### Wenku8 clients

[MewX/light-novel-library_Wenku8_Android](https://github.com/MewX/light-novel-library_Wenku8_Android) is a mature, GPL-2.0-or-later Android client with search, catalog, volume, chapter, login, and reader code that can be studied. Its repository explicitly says Wenku8 API abuse led the author to move requests to the author's own Cloudflare Worker relay, and the README notes the site owner did not permit publishing the API. The release page lists v1.30; the app can inform a site-specific adapter, but its relay is not a public, supported API for another app to depend on. Do not reuse a baked-in relay URL or credentials as though they were authorized public infrastructure.

[15dd/wenku8reader](https://github.com/15dd/wenku8reader) was archived on 2026-02-24, and its README says it is no longer maintained and no longer works. It is not a current reuse base.

[mikufoxxx/Wenku8_Flutter](https://github.com/mikufoxxx/Wenku8_Flutter) has an official v0.5.6 release dated 2026-11-03 and states that online listings/content come from Wenku8 while local books are user-imported. Its current product supports Wenku8 and local import, not arbitrary source plugins. The repository also says its public source snapshot references omitted modules and cannot be built independently. An open issue dated 2026-11-10 reports trouble connecting to the site. This makes it the most current one-source client in this comparison, not a general-purpose source package or proof that Wenku8 is reachable in the current environment.

[Xempastissimo/LightNovelReader](https://github.com/Xempastissimo/LightNovelReader) is a Kotlin/Compose Wenku8 reader, currently v0.1.2-alpha (release dated 2026-09-12), GPL-3.0. Its README documents the non-API HTML route and an alternate dl.wenku8.com plain-text whole-book package; the author reports that the latter returned a complete file without cookies in their own checks. This is a useful implementation reference because it keeps the browser challenge path separate from the direct download host, but it is explicitly alpha, supports only Wenku8, and the dl result was not independently rechecked for this report. The app's own website checks found Cloudflare 403 on the regular Wenku8 domains.

[XiaHusuper/light-novel-library](https://github.com/XiaHusuper/light-novel-library) is a Java/WebView client, but its README says online use needs a proxy tool and that Wenku8 registration is closed. The original project code is MIT, while the same README identifies a separately distributed native API runtime from the Miku app; its third-party notice assigns that component GPL terms. It is not a clean parser-only transplant, and it remains a Wenku8-only reader.

### Plugin ecosystems

[LNReader](https://github.com/LNReader/lnreader) uses a separate TypeScript plugin repository, language folders, a built manifest, and a documented plugin contract. The [Kakuyomu plugin](https://github.com/LNReader/lnreader-plugins/blob/master/plugins/japanese/kakuyomu.ts) directly reads Kakuyomu's serialized works, table of contents, and episode pages; this is relevant for Japanese originals available as web fiction, not for discovering all commercial Japanese light-novel volumes. The [Linovelib plugin](https://github.com/LNReader/lnreader-plugins/blob/master/plugins/chinese/linovelib.ts) sends search, detail, and chapter parsing to an external Linovelib Descramble Server, with a default local endpoint at http://localhost:5301. That dependency makes it unsuitable as a ready-to-run APK source unless the user also runs/configures that server. Porting either plugin means translating its site logic and runtime assumptions, not importing the plugin file as-is.

[Shosetsu](https://shosetsu.app/help/guides/extensions.html) uses Lua extensions for site-specific search, novel, and chapter retrieval. Its repository documentation describes community repositories and warns that Universe sources vary in quality and origin; its FAQ says some extensions are outdated. It is a useful example of source/plugin separation, but it is not a Kotlin/Legado extension format and does not establish dependable Japanese published-volume coverage.

[The checked Dantotsu fork](https://github.com/albertxiao/Dantotsu) marks light-novel extensions as not working. The original rebelonion repository returned HTTP 451 in the principal's check; its current state was therefore not independently inspected. This evidence does not establish the status of every Dantotsu fork.

### Legado source sets

[ZWolken/Light-Novel-Yuedu-Source](https://github.com/ZWolken/Light-Novel-Yuedu-Source) is the clearest ready-made match to the requested language split: it publishes separate Japan-based translated-LN, China-based LN, and Japanese-original source files. Its README says it is in a “half-maintenance” period, some sources require login, some search functions are unreliable, and no source is guaranteed to work. It also asks redistributors to keep the source name and original comments. The repo advertises MIT licensing; preserve attribution and source-specific notes when taking an individual rule.

[yolo52/Yuedu](https://github.com/yolo52/Yuedu) publishes a smaller Legado “light novel” JSON group and declares GPL-3.0. The listed source names span commercial/community Chinese LN sites and Wenku8, so it can be mined for candidate sources, but the repo says it is updated irregularly and cannot guarantee current availability. The recent bounded checks against several candidate hosts (including WenkuChina timing out and 37Novel/qxsw TLS errors) reinforce that a JSON URL being live does not establish that its target site works.

One exception to the mostly failed host checks is the Mangacopy rule in Yolo's set. In the supplied live test, anonymous search for the full title 回复术士的重启人生 returned one exact title match, detail identified 月夜淚, and the volume listing contained nine volumes. The first volume endpoint reported no login/VIP lock; its UTF-8 text response was 329,063 bytes with 121,383 characters and no replacement characters. Its chapter line ranges and image markers give the importer usable boundaries. This makes Mangacopy the first sensible additional source to evaluate in-app, while limiting the claim to this work's first volume; do not infer all-volume completeness or permission to redistribute its text. The tested [search endpoint](https://api.mangacopy.com/api/v3/search/books?limit=20&offset=0&q=%E5%9B%9E%E5%A4%8D%E6%9C%AF%E5%A3%AB%E7%9A%84%E9%87%8D%E5%90%AF%E4%BA%BA%E7%94%9F&_update=true), [book endpoint](https://api.mangacopy.com/api/v3/book/huifushushidechongqirensheng), and [volume-list endpoint](https://api.mangacopy.com/api/v3/book/huifushushidechongqirensheng/volumes) are examples of the current API surface, not a published stability promise.

[jiwangyihao/source-j-legado](https://github.com/jiwangyihao/source-j-legado) is among the most focused current Legado rule sets. Its repository license is marked MPL-2.0, but complete source files include an extra author statement asking users to open an issue and receive approval before reposting or adapting a complete source, and forbidding repackaging the complete set into a general-purpose book-source collection. This report therefore treats it as a source of examples and a user-import option, not material to bundle into 柘栯小说 by default.

### Crawler and EPUB options

[lncrawl/lightnovel-crawler](https://github.com/lncrawl/lightnovel-crawler) is the strongest maintained generic crawler located in this search. Its stable release v4.14.0 is dated 2026-08-03; the project documents CLI, web-server, REST API, EPUB export, and diagnostics that reject empty/challenge responses instead of silently calling them chapters. Its development [SOURCES.md](https://github.com/lncrawl/lightnovel-crawler/blob/dev/SOURCES.md) advertises 361 sources / 11 languages, but its Japanese section lists only ncode.syosetu.com and syosetu.org, and its Chinese section includes 69shuba.cx, ixdzs8.com, shuhaige.net, trxs.cc, and other web-fiction sites. The long total is therefore not evidence of broad Japanese light-novel book coverage. These are mostly site/chapter crawlers, so a generated EPUB may not preserve an official publisher's volume/chapter organization. The project is GPL-3.0 and a REST integration requires the crawler server to run on a device or host.

[auto-novel/auto-novel](https://github.com/auto-novel/auto-novel) is the source for Novelia, a GPL-3.0 machine-translation library supporting web, library/volume, and local novels. The public site currently exposes an anonymous Wenku catalog route tested for one example; the regular /api/novel route returned 401 anonymously in the supplied checks. For 回复术士, metadata listed 10 volumes but only 9 had Chinese EPUB files; an EPUB document count and the app's imported chapter count differed. Treat it as an optional downloadable-volume catalog, not a complete, stable discovery API. The official README warns that personal deployment is not its intended configuration and forward compatibility is not guaranteed.

## Recommended reuse path

1. **Keep Legado as the source contract.** Add only user-selected source groups, with the source name, target site, original comments, last checked date, and any login/server requirement visible. Start by validating the Mangacopy rule for first-volume chapter boundaries, then consider individual candidates from ZWolken's MIT release; do not import a whole collection as a guarantee of availability.
2. **Keep Wenku8 isolated.** For no-login use, request only the normal public pages or downloads that are reachable. On the tested network the main Wenku8 domains returned 403, so show the source as unavailable and offer a browser handoff if a user chooses to resolve site access. Never silently route through MewX's personal relay or pretend the private relay is an official API.
3. **Add Japanese original web fiction only as a distinct category.** Kakuyomu and Ncode/Syosetu-style adapters can provide serialized chapters where the site permits access; they do not supply publisher metadata or volume completeness. Test a whole known work before advertising a source as complete.
4. **Offer Novelia as an EPUB-volume import source.** Distinguish the public Chinese EPUB files (volumeZh) from generated machine translations (volumeJp), check expected volume availability and imported chapter structure, and keep this route separate from ordinary live source search. For a missing volume or unverified chapter mapping, say so in the UI.
5. **Do not add a background server for the default APK.** Lightnovel Crawler is the better-maintained multi-site crawler, but it belongs as an optional power-user/self-hosted integration if a server later becomes an explicit product requirement.

This path reuses the app's current Legado rule engine and EPUB importer; it does not require adopting LNReader's TypeScript runtime, Shosetsu's Lua runtime, or a novel-content backend. The principal limitation remains site availability and per-title completeness, which must be reported per source and title rather than inferred from collection size.
